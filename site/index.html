Before writing code

What the research killed

Spotify's API has quietly lost a lot of surface area since 2024. Half this project's design comes from finding out what is no longer possible — and then routing around it.

✕ Dead end

Canvas videos

The looping clips Spotify shows have no public API. The only access is reverse-engineered endpoints that violate the ToS and break without notice. Cut deliberately rather than shimmed.

✕ Dead end

Audio analysis

audio-features and audio-analysis were deprecated for new apps on 2024-11-27 with no replacement — new apps get 403. Beat-synced visuals off Spotify's own data are simply not buildable any more.

✕ Doesn't exist

Queue reordering

You can read the queue and append to it. There is no reorder and no remove endpoint. So the UI won't offer a drag handle that can't work — a missing affordance beats a lying one.

✓ Route found

Tempo via ISRC

Track objects still expose external_ids.isrc, which isn't deprecated. Look that up in a free BPM database and you get a phase-locked beat pulse while remote-controlling audio playing somewhere else entirely.

✓ Route found

A real FFT

If the Pi runs librespot, the audio decodes locally. Its pipe backend emits raw s16le/44.1k PCM — tee that stream and you get a genuine spectrum analyser off the real waveform. What Winamp actually did.

⚠ Hardware trap

The Pi Zero has no DSI

The Zero 2 W is the only current Pi without a display connector, so it can't use the official touchscreen — it needs HDMI plus separate touch wiring. The board that seemed right for a tidy object makes it least tidy.

⚠ Hardware trap

The Pi 5 moved the goalposts

Its DSI connector is 22-pin, not 15 — the official display needs an adapter cable. And the 3.5mm jack is gone, so on-device audio needs a USB DAC. Two second orders, avoided.

⚠ Constraint

No push, ever

There's no websocket for playback state, so it must be polled. Adaptive polling plus local progress interpolation keeps the bar smooth at refresh rate while sitting far under the rate limit.

Decision D-006 → D-010

The call I got wrong

D-006: No audio-reactive visuals. The endpoints are gone, so all motion must be procedural.

That was too pessimistic. The deprecation removes Spotify's analysis, not every route to a beat signal. Tempo can be resolved by ISRC lookup, and when the Pi plays the audio itself there's a real PCM stream to run an FFT over.

So the visualiser got three interchangeable reactivity providers behind one uniform contract — procedural, BPM-locked, and true FFT. The shaders never know which one is feeding them, and quality degrades gracefully instead of failing.

The decision log keeps superseded entries with the reasoning intact. Knowing why a wrong turn was wrong is worth as much as the right answer — and it stops a future session re-litigating it.

Choices, with reasons

Stack

Two processes on the Pi. The server does everything expensive once per track; the UI is a pure renderer of a pushed payload — which keeps OAuth tokens out of the browser and the GPU free for the visualiser.

TypeScript — one language, shared types Fastify — localhost only Svelte — no VDOM runtime WebGL2 — GLES 3.1 via Mesa V3D Vitest + fake Spotify server Playwright — E2E, no real creds in CI Raspberry Pi 5 + Touch Display 2 librespot — optional PCM tap

A quiet win: half-resolution rendering was chosen to cut fragment cost 4×, then kept because it looked like the lo-fi aesthetic we wanted. It turns out that's almost exactly the PS1's native output. The performance dial, the art direction and the period reference are the same slider.
